description: 'Use after a non-privileged Windows foothold (service account, web/db shell, or session) that is not yet SYSTEM/admin. Covers token-privilege abuse (SeImpersonate/SeAssignPrimaryToken), service/registry/path misconfig, and EDR-aware delivery, favouring in-process execution over dropping scannable binaries.'
mcps: pa-c2
---
Authorized targets only. Doctrine, not a fixed script. (1) Enumerate privileges and the defensive posture before acting: token privileges, OS build, EDR/AV state. (2) When SeImpersonate/SeAssignPrimaryToken is held, escalate to SYSTEM by token abuse, but SELECT THE COERCION VECTOR BY OS BUILD: the DCOM/OXID-resolver family works on current Server builds; the EFSRPC/print-spooler family is mitigated on recent builds and its stock binaries are AV-quarantined, so do not rely on it there. (3) EDR-aware delivery is the priority: prefer in-process execution over writing tool binaries to disk. When the foothold is MSSQL-sysadmin, run the escalation in-process via SQLCLR inside the SQL Server process (trusted-assembly registration; use a direct build because the CLR host blocks reflective byte-array loads) instead of dropping an executable that gets quarantined; otherwise live-off-the-land / in-memory. Reference any tool by its staged path; never inline a binary. (4) Drive the session and post-exploitation through the pa-c2 MCP. (5) Confirm with an identity oracle (whoami = NT AUTHORITY SYSTEM) and remove staged objects afterward. MITRE T1134, T1068.
